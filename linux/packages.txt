# bwrap is a hard startup failure rather than a silent fall back to running

# === Server observability ===
# dotfiles/mise/config.toml notes these two have no macOS aqua binaries and are
# "kept in brew on Mac" — but no mise entry exists for them, so on Linux apt is
# the one thing that actually provides them.
btop

time           # /usr/bin/time — the BINARY, which is not the bash builtin. Agents
               # profiling a step reach for `/usr/bin/time -v` (peak RSS, wall
               # clock) and get rc=127 because only the builtin exists, and the
               # builtin supports neither -v nor a format string. `command -v
               # time` answers "time" either way, so the check that would catch
               # this passes on a box where it is missing. Cost a profiling
               # script on 2026-08-07.

# === DNS diagnostics ===
# bind9-dnsutils, NOT dnsutils: the transitional package is gone in trixie
# (`apt-cache policy dnsutils` answers "Candidate: (none)"), so the habitual
# name resolves to nothing and installs nothing.
#
# The box already ships /usr/bin/host, pulled in as bind9-host by another
# package's dependencies, so `command -v host` succeeds and the machine LOOKS
# equipped for DNS triage while dig is absent — the same false-negative shape
# as the `time` entry above.
#
# Cost a DNS misdiagnosis on 2026-08-07: a triage loop running `dig @<upstream>`
# against all three of Linode's resolvers returned empty for every one, which is
# indistinguishable from "no upstream answered", and nearly indicted resolvers
# that were in fact healthy. host(1) is not a substitute — comparing
# `dig @1.1.1.1 <name>` against `dig @<local-resolver> <name>` is the test that
# separates a broken resolver from a broken name, and it was the unavailable one.
bind9-dnsutils

# === Containers — for your shell, CI, AND agents ===
# Rootless podman provides the Docker-compatible API socket testcontainers-go looks
# for. Until 2026-08-04 it was deliberately unreachable from inside an agent
# sandbox; `allowAllUnixSockets` is now on, so agents run the container-backed
# tiers themselves. That switch is all-or-nothing on Linux — seccomp cannot filter
# a socket by path, and `allowUnixSockets` says "macOS only ... ignored on Linux"
# in its own schema.
#
# What it costs is NOT mainly the SSH agent, which is what this comment used to
# warn about: signing and pushing already use an on-disk key, so no Touch ID tap
# was being protected. The real cost is that the runtime executes OUTSIDE the
# sandbox, so image pulls originate outside the proxied network path and bind
# mounts reach denied paths. Read linux/sandbox.md before changing this.
podman
uidmap         # newuidmap/newgidmap — rootless podman cannot map subuids without it
passt          # pasta: podman 5's default rootless network backend
podman-remote  # `podman --remote`; also what a toolbox container needs to drive
               # the host socket when loopback TCP is blocked in-session

# NOT here on purpose: docker-compose. `podman compose` is only a wrapper and
# fails with "looking up compose provider failed" until a real provider exists,
# so one IS required — but docker-compose Recommends docker-cli, and this file is
# installed without --no-install-recommends. A real /usr/bin/docker would then
# talk to /var/run/docker.sock, which does not exist on a rootless box, and would
# shadow ~/.local/share/kind-shims/docker, which restore.sh installs. restore.sh
# installs the compose provider in its own --no-install-recommends call instead.
